# LinguaDub

**Every Voice. Every Language. Everywhere.**

LinguaDub is an AI video dubbing and localization platform. Upload a video or audio file, choose target languages, assign voices to each detected speaker, review the translated script and export a dubbed MP4 with subtitles.

## Stack

- Next.js 16 (App Router, `proxy.ts`), React 19, TypeScript
- Tailwind CSS 4, Inter and Manrope, Lucide icons
- Supabase: Postgres with Row Level Security, Auth, Storage and Realtime
- ffmpeg (bundled through `ffmpeg-static`) for audio extraction, synchronisation and rendering
- AI provider adapters for ElevenLabs, OpenAI and DeepL

## What is implemented

| Area | Details |
| --- | --- |
| Marketing site | Home with an interactive product walkthrough, Platform, Solutions, Features and Pricing. Footer is `© 2026 LinguaDub`. |
| Authentication | Email and password sign up with email verification, login, logout, forgot and reset password, persistent sessions, protected routes (`src/proxy.ts` plus server checks in every layout and API route), profile management. |
| Dashboard | Overview built from live data: projects, completed and processing counts, minutes processed, languages, monthly usage, storage, recent projects and activity. |
| Projects | Create, rename, edit, duplicate, delete, save drafts, upload media, source and target languages, status, approval state and full processing history. |
| Uploads | Validated type and size, storage quota check, direct upload to a private bucket through a one time signed URL, with progress. |
| Pipeline | Background jobs: extract audio, transcribe, detect speakers, translate, review, assign voices, generate speech, synchronise, generate subtitles, render and export. Each job reports a real status with retries and backoff. |
| Workspace | Video or audio preview with dubbed track playback and subtitle overlay, waveform drawn from the actual audio, speaker tracks and dub track timeline, dialogue list, translation editor, emotion and accent controls, timing (start, end, speed, pause, offset), per line playback, approvals, exports and subtitle timing offsets. |
| Voices | Voice library from the connected provider with language, accent, gender presentation and style filters, previews generated by the provider, and favourites. |
| Voice cloning | Consent first: the voice owner verifies their email, records the consent statement and signs. Only then can samples be uploaded and a voice created. Revoking consent deletes the voice at the provider. |
| Subtitles | SRT and VTT for original and translated dialogue, edited text, global timing offset, embedded `mov_text` subtitles in MP4. |
| Export | MP4 (original video stream copied, so resolution is preserved), MP3, WAV, SRT and VTT. Private files are served through 10 minute signed links. |
| Team | Invitations with seat limits, six roles (Owner, Administrator, Editor, Translator, Reviewer, Viewer), role changes, removal, review and approval flow, activity log, notifications. |
| Billing | Three plans linked to the Selar checkout links in order. Plans activate only from a verified Selar payment notification. Minutes, storage, seats, target languages per project and cloned voices are enforced on the server. |

Lip synchronisation is **not** implemented and is described as unavailable on the site. The provider adapter design allows it to be added later.

## Environment variables

Copy `.env.example` to `.env.local` for development and set the same variables in your host for production. Values marked server only must never be exposed to the browser. Only variables starting with `NEXT_PUBLIC_` reach client code.

| Variable | Required | Purpose |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | yes | Public URL used in email, consent and invitation links |
| `NEXT_PUBLIC_SUPABASE_URL` | yes | Supabase project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | yes | Supabase anon key (safe for the browser, RLS applies) |
| `SUPABASE_SERVICE_ROLE_KEY` | yes, server only | Used by server routes and background jobs after permission checks |
| `CRON_SECRET` | yes, server only | Protects `/api/jobs/process` |
| `ELEVENLABS_API_KEY` | recommended | Speech to text with speaker identification, voices, emotion, voice cloning |
| `OPENAI_API_KEY` | optional | Whisper transcription, translation, voices |
| `DEEPL_API_KEY` | optional | Translation |
| `STT_PROVIDER`, `TRANSLATION_PROVIDER`, `TTS_PROVIDER`, `VOICE_CLONING_PROVIDER` | optional | Choose a provider when several keys are set |
| `SELAR_WEBHOOK_SECRET` | yes for billing | Authenticates Selar payment notifications |
| `TRIAL_MINUTES` | optional | Minutes allowed without a subscription (default 0) |
| `RESEND_API_KEY`, `EMAIL_FROM` | optional | Emails consent requests and invitations (otherwise links are shown to copy) |
| `NEXT_PUBLIC_MAX_UPLOAD_MB` | optional | Upload limit, keep in line with your Storage limit |

A feature only switches on when its provider key is present. Languages shown in the app are the ones every configured provider supports for that step (`src/lib/providers`).

## Setup

1. **Install:** `npm install`
2. **Create a Supabase project.**
3. **Run the migration and expose the schema:** LinguaDub lives in its own `linguadub` Postgres schema with `linguadub-*` storage buckets, so it can share a project with other apps. After running the SQL, add `linguadub` under Project Settings > API > Exposed schemas. Paste `supabase/migrations/0001_linguadub_schema.sql` into the SQL editor, or run `supabase db push`. It creates every table, RLS policy, the private storage buckets (`media`, `generated`, `exports`, `voice-samples`), the job queue function and Realtime publication entries. It can be re-run safely.
4. **Configure Auth** (Authentication settings):
   - Site URL: your production URL.
   - Redirect URLs: add `https://YOUR_DOMAIN/**` and `http://localhost:3000/**`.
   - Keep **Confirm email** enabled.
   - SMTP: configure a custom SMTP provider for production email delivery.
5. **Storage:** raise the global file size limit (Storage settings) if you accept large videos. The default free tier limit is 50 MB.
6. **Environment:** fill in `.env.local`.
7. **Run:** `npm run dev`, then open http://localhost:3000.

## Background processing

Long work runs in jobs stored in `processing_jobs` and claimed atomically with `FOR UPDATE SKIP LOCKED`.

- Starting a step schedules the worker with `after()` in the same serverless function (up to 300 seconds, set by `maxDuration`).
- Voice generation is resumable. Long projects continue in the next worker run without losing progress.
- Failed steps retry with exponential backoff. Permanent errors (for example a missing provider key) stop and explain the fix.
- An open workspace nudges queued work (`/api/jobs/kick`), and `/api/jobs/process` can be called by any scheduler with `Authorization: Bearer CRON_SECRET`.
- `vercel.json` includes a daily cron that works on every Vercel plan. On Vercel Pro, change it to `*/5 * * * *`.
- For heavy workloads, run the standalone worker on any Node host: `APP_URL=https://YOUR_DOMAIN CRON_SECRET=... npm run worker`.

## Deployment (Vercel)

1. Import the GitHub repository in Vercel.
2. Add the environment variables above (Production and Preview).
3. Deploy. ffmpeg is bundled into the API functions through `outputFileTracingIncludes` in `next.config.ts`.
4. Set Supabase Auth Site URL and Redirect URLs to the deployed domain.
5. Configure the Selar notification URL (below).

Any Node host works too: `npm run build` then `npm start`.

## Selar payments

The three pricing cards use the Selar checkout links in the order given:

1. https://selar.com/47plan?currency=USD
2. https://selar.com/57plan?currency=USD
3. https://selar.com/97plan?currency=USD

Plan names, prices, billing frequency and limits live in `src/config/plans.ts`. **The Selar pages could not be reached from the build environment, so the names and prices there (Starter $47, Growth $57, Scale $97, monthly) come from this repository's earlier README. Confirm them against the live Selar products and edit that one file.**

Clicking a checkout button never activates a plan. Activation happens only when Selar notifies LinguaDub:

- Notification URL: `https://YOUR_DOMAIN/api/webhooks/selar?secret=SELAR_WEBHOOK_SECRET`
- Requests are accepted with the shared secret, or with an HMAC SHA256 signature of the raw body in `x-selar-signature`.
- The plan is identified by the product slug (`47plan`, `57plan`, `97plan`) and matched to the LinguaDub account with the same email. Amount and currency are checked. Each notification is stored once (idempotent).
- Customers who paid before signing up can link the payment from **Billing** with their order reference. The payment email must match their account.
- If Selar does not offer notifications on your account, an administrator can activate a plan with SQL:
  `insert into subscriptions (org_id, plan_id, status, current_period_end) values ('ORG_ID', 'plan_57', 'active', now() + interval '1 month');`

## Brand

`src/config/brand.ts` sets `BRAND_MARK`. It defaults to the uploaded LinguaDub artwork (`public/brand/linguadub-mark.png`). The six concept marks from the selection board are available as `concept1` to `concept6`. Change the value to switch the logo everywhere. Replace `src/app/icon.png` to change the favicon.

## Security

- Every tenant table has `org_id` and Row Level Security. Helper functions check membership and role without recursion.
- API routes check the caller's role in the workspace that owns the record before any service role operation.
- Media, generated audio, exports and voice samples are in private buckets. Downloads use short lived signed URLs after a membership check.
- API keys and the service role key are read only on the server.
- Cloned voices require verified consent from the voice owner and are only usable inside the workspace that created them.

## Testing performed

An end to end suite was run against a local Supabase stack (Postgres 17, Auth, Storage, PostgREST, Mailpit), with the provider HTTP calls answered by a local stand in for the OpenAI API so the real pipeline could run offline. Real ffmpeg processing, storage, database, queue and UI were exercised:

- Sign up validation, email verification, refused login before verification, protected route redirects, login, wrong password, logout, persistent sessions, password reset by email.
- Selar notification: wrong secret rejected, verified payment activates a plan, duplicates ignored, upgrade.
- Project creation with upload, extraction, transcription, translation, review, line edits, voice assignment, generation, synchronisation, subtitles and rendering. The exported MP4 was inspected: original H.264 stream and resolution kept, AAC dub track, embedded subtitles, full duration.
- Regeneration only voices and bills changed lines.
- Workspace isolation: another account cannot view, edit, delete, upload to or download from a project, and direct database queries return no rows.
- Team: seat limit, invitation, translator permissions, review submission and approval, activity log.
- Voice consent: owner email verification required, unverified visitors refused, verified consent stored with signature and recording, cloning safeguards.
- Responsive layouts at phone width, and a copy check for dashes and emojis on every page.

Live provider calls (ElevenLabs, OpenAI, DeepL) need real keys and were not exercised in this environment.
